# Building APKs — ServeSaathi

How to produce installable Android builds for this project (Expo SDK 56, React Native 0.85,
prebuild/CNG workflow — the `android/` folder is **generated** and gitignored).

---

## 1. Prerequisites (one-time setup)

| Tool | Version | Notes |
|------|---------|-------|
| Node.js | 20+ | `node -v` |
| JDK | 17 | `java -version` — Android Gradle Plugin requires 17 |
| Android Studio | latest | installs the SDK + emulator |
| Android SDK | API 35 (compile), Build-Tools | via Android Studio → SDK Manager |

Environment variables (add to `~/.zshrc`):

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator
```

Verify a device is reachable: `adb devices` (physical phone with USB debugging, or a running emulator).

---

## 2. Regenerate the native project (when needed)

The `android/` folder is generated from `app.json`. Regenerate it whenever you change:
app icon / adaptive icon, splash screen, app name, package id, permissions, or add a
config-plugin dependency.

```bash
npx expo prebuild -p android --clean
```

> `--clean` deletes and recreates `android/`. That is safe here — the folder is gitignored
> and has no manual native edits. Never hand-edit files under `android/`; change `app.json`
> and re-run prebuild instead.

Pure JS/TS changes do **not** need a prebuild.

---

## 3. Debug APK (development / QA hand-off)

### Option A — build & install in one step
```bash
npx expo run:android
```
Builds the debug APK, installs it on the connected device/emulator, and starts Metro.

### Option B — just the APK file
```bash
cd android
./gradlew assembleDebug
```
Output:
```
android/app/build/outputs/apk/debug/app-debug.apk
```
Install manually with `adb install -r app-debug.apk`.

> Debug builds load JS from Metro. For a QA build that runs **without** a laptop,
> use the release APK below.

## 4. Release APK (standalone, shareable)

### 4.1 Create a signing keystore (one-time)

```bash
keytool -genkeypair -v \
  -keystore servesaathi-release.keystore \
  -alias servesaathi \
  -keyalg RSA -keysize 2048 -validity 10000
```

Keep the keystore **out of git**. Store it (and the passwords) in the team vault.
Losing it means you can never update the app under the same signature.

### 4.2 Point Gradle at the keystore

Create/append `android/gradle.properties` values via `~/.gradle/gradle.properties`
(machine-local, survives prebuild):

```properties
SERVESAATHI_UPLOAD_STORE_FILE=/absolute/path/servesaathi-release.keystore
SERVESAATHI_UPLOAD_KEY_ALIAS=servesaathi
SERVESAATHI_UPLOAD_STORE_PASSWORD=********
SERVESAATHI_UPLOAD_KEY_PASSWORD=********
```

Then in `android/app/build.gradle` add a `release` signingConfig referencing those
properties. **Caveat:** because `android/` is regenerated by prebuild, this edit is wiped
on every `--clean`. Two durable choices:

- **Recommended:** use EAS Build (section 5) — signing is managed for you, nothing to re-edit.
- Or keep a small patch/script that re-applies the signing block after each prebuild.

Without a signing config, `assembleRelease` signs with the **debug key** — fine for internal
testing, not for the Play Store.

### 4.3 Build

```bash
cd android
./gradlew assembleRelease
```
Output:
```
android/app/build/outputs/apk/release/app-release.apk
```

For the Play Store use an **AAB** instead:
```bash
./gradlew bundleRelease
# → android/app/build/outputs/bundle/release/app-release.aab
```

## 5. Alternative: EAS Build (cloud, no local Android setup)

```bash
npm install -g eas-cli
eas login                       # servesaathidevelopment account
eas build:configure
eas build -p android --profile preview   # produces an installable APK
eas build -p android --profile production # produces an AAB for the Play Store
```

`preview` profile builds an APK you can download from the EAS dashboard and share directly.
Signing keys are generated and stored by EAS on first build.

---

## 6. Version bumps before a build

Edit `app.json`:

```jsonc
"version": "1.0.1",          // user-visible version
"android": {
  "versionCode": 2           // must increase on every Play Store upload
}
```

Then re-run prebuild (section 2) so the native project picks them up.

## 7. Troubleshooting

| Symptom | Fix |
|---------|-----|
| `configureCMakeDebug` fails with `A restricted method in java.lang.System has been called` (often alongside `SDK XML versions up to 3` warnings) | Gradle is running on a too-new JDK (24/25). Point it at Android Studio's bundled JDK 21 by adding to `~/.gradle/gradle.properties`:<br>`org.gradle.java.home=/Applications/Android Studio.app/Contents/jbr/Contents/Home` |
| Icon/splash changes not visible | You must rebuild the APK — Metro reload can't change native resources. Re-run prebuild `--clean` then build. |
| `mergeReleaseResources` → `AAPT: error: file failed to compile` on an image | The image is not what its extension claims (e.g. JPEG data in a `.png` — Figma asset exports do this). Verify with `file <path>` and re-encode: `python3 -c "from PIL import Image; Image.open(p).convert('RGB').save(p,'PNG')"`. Release builds validate images; debug builds don't. |
| Same AAPT error persists after fixing the image | Gradle cached the old copy — delete `android/app/build/generated/res/react` and rebuild. |
| `SDK location not found` | Set `ANDROID_HOME` (section 1) or create `android/local.properties` with `sdk.dir=...`. |
| Gradle out-of-memory | Add `org.gradle.jvmargs=-Xmx4g` to `~/.gradle/gradle.properties`. |
| Stale build weirdness | `cd android && ./gradlew clean`, and clear Metro with `npx expo start -c`. |
| Release APK crashes at boot but debug works | Check Metro isn't required: release must bundle JS — build via the commands above, not by exporting manually. |

## Quick reference

```bash
# QA build on a device, end to end
npx expo prebuild -p android --clean   # only if native config changed
npx expo run:android                   # debug, needs Metro

# Shareable standalone APK
cd android && ./gradlew assembleRelease
# → android/app/build/outputs/apk/release/app-release.apk
```
